# 轻阅 · LightReader

一款隐私优先、专注阅读的 TXT / DOCX / PDF 阅读器，提供 Android 应用和独立网页端。它把文件导入、批注、全文搜索、格式保留编辑和可选 AI 阅读助手放在同一个轻量流程里；不要求账号，也不强制使用云端服务。

## 适合谁

- 想在手机上安静阅读长篇 TXT 或 Word 文档的人。
- 需要边读边做批注、回到上次进度，并把修改后的 Word 导出的人。
- 想使用自己的 AI 服务商，而不是把阅读流程锁定在单一平台的人。

## 主要能力

- **TXT / DOCX / PDF 导入**：通过 Android 系统文件选择器打开本地文件；TXT 支持 UTF-8、UTF-16 和 GB18030 常见编码。
- **PDF 阅读与批注**：离线保留原版式，支持页码跳转、缩放、长按选文高亮批注及整页批注（含扫描页）；批注可编辑、删除、跳转，重新打开后恢复。支持将高亮、便签和中文批注正文写入“文件名-含批注.pdf”副本，保留原文件、原页面及已有 PDF 批注。副本可在支持 PDF 批注的阅读器中查看，轻阅也可读取副本内的批注。笔记另可导出 Markdown 或备份/恢复 JSON。
- **长文阅读**：大文本分块加载，保留阅读进度；支持字号、行距、段落间距、浅色/深色主题。
- **DOCX 解析与编辑**：识别标题、列表、表格、段落对齐、底色和常见文字样式；编辑后尽量保留原 Word 包结构并导出。
- **批注工作流**：选中文字添加批注，支持全局批注、批注列表、冲突检查，以及把 AI 回答加入批注；原文变动后的批注保留为待定位，可手动重新绑定。
- **笔记导出与恢复**：导出当前文档的 Markdown 笔记或 JSON 备份，恢复时去重并保留冲突副本。
- **搜索与目录**：在当前文档内搜索，支持 TXT 章节目录。
- **可选 AI 助手**：支持 Responses 和 Chat Completions 两类协议，可保存多个渠道；Responses 渠道可按服务商能力启用联网搜索与引用。
- **上下文划词讲解**：结合章节和附近段落，默认要求简短回答并区分原文与补充知识；按需展开本次原文依据，收起后继续原位置阅读。
- **整本书分析**：打开文档后进入“AI 对话 → 整本书分析”，相邻短章节合并为最多 7000 字符的分析批次，完整读取正文后分层生成全书概要、内容脉络、核心观点及思考问题，避免每个小标题各发一次请求。支持进度、暂停/失败续跑、本机保存和 Markdown 导出；分段分析可回到原文，知识库仍保留具体章节/页码。旧版未完成任务保留已分析内容及引用编号，只合并尚未处理的短章节。全书问答结合概要及检索的有限原文，显示实际来源供核对。开始前展示预计调用次数，开始后展示剩余次数；启动会向所选渠道发送正文，可能计费。PDF 仅分析可提取文字，不包含 OCR 或图片理解。
- **每本书的本地 RAG 知识库**：完整分析后自动索引原文，已有完整报告重开后也会补建。采用 BM25＋本地 BGE 中文语义向量混合检索，无需 Embedding API。Android 使用 24.0 MB 的 q8 模型，网页端使用 94.9 MB 的 fp32 模型；模型由所有书共用，各书单独保存向量。支持语义建库进度、暂停续建；加载中、暂停或模型失败时保留关键词检索。知识库面板可检索并定位原文，问答向所选 AI 渠道发送至多四段原文及全书概要；正文改变后停用旧索引，重新分析后更新。不提供跨书检索。
- **文档对话保存**：选文和独立对话随文档保存在本机，可在重新打开文档后继续；独立对话不会自动发送文档正文。
- **最近文件**：记录最近打开项目，可置顶或移除；原始文件不会被应用覆盖，DOCX 修改以私有草稿保存。

## 与常见同类产品的区别

下表按产品形态概括，具体行为会随产品版本和服务商而变化。

| 维度 | 轻阅 | 通用办公套件 | 云端 AI 阅读器 | 传统 TXT 阅读器 |
| --- | --- | --- | --- | --- |
| 核心目标 | 手机端专注阅读 + 批注 | 全面的编辑、协作和办公 | 围绕对话和摘要阅读 | 只解决纯文本阅读 |
| 数据路径 | 本地优先；AI 仅在主动发送时出网 | 常见功能较重，常与账号/云盘结合 | 通常需要上传文档到服务端 | 多数只在本地处理 |
| DOCX 体验 | 样式感知、可编辑、尽量保留原包后导出 | 编辑能力强，但阅读流程更复杂 | 依赖服务端解析，离线能力有限 | 往往不支持或只做纯文本化 |
| AI 选择 | 用户自带 HTTPS 渠道，可切换服务商 | 取决于套件内置服务 | 常绑定单一模型或订阅 | 通常没有 |
| 使用负担 | 无账号、无强制同步、界面聚焦 | 功能多，学习和资源成本更高 | 依赖网络、账号与服务策略 | 功能轻，但扩展性有限 |

轻阅的取舍很明确：不追求办公套件的“大而全”，而是把本地阅读、可恢复的批注和可控的 AI 辅助做成一条短路径。

## 隐私与安全

- **本地计算**：Android 模型随安装包提供；网页端从当前网站加载模型并使用浏览器缓存，本地向量计算不发送书籍正文。构建准备阶段需下载公开模型和运行库；运行时仅主动 AI 分析/问答会将材料发送到所选渠道。本项目没有账号系统、埋点或云端同步代码。
- **密钥不进 WebView**：API Key 使用 Android Keystore 加密保存，网页层只收到 `hasKey` 状态，不会读回密钥明文。
- **HTTPS 强制**：AI 地址必须是 HTTPS；应用关闭明文流量，并拒绝把外部链接加载进本地阅读页。
- **解析边界**：DOCX XML 禁用 DOCTYPE、外部实体和外部 DTD；导入、解析、响应和编辑草稿都有大小上限。
- **输出转义**：DOCX 内容写入本地 HTML/XML 前会转义，避免文档文本被当成脚本执行。
- **本机数据隔离**：批注、阅读进度和 DOCX 草稿保存在应用私有存储；系统级备份是否启用由 Android 设备设置决定。
- **发布防线**：`local.properties`、构建产物、IDE 文件、签名文件和常见密钥文件已加入忽略规则；提交前仍应人工检查暂存区。

使用 AI 时，选中文字或问题会发送到所选服务商。请不要把敏感材料发送给未经信任的服务商，并为不同用途使用最小权限、可撤销的 API Key。

更具体的漏洞报告方式见 [SECURITY.md](SECURITY.md)。

## 网页端

需要 Node.js 20 或更新版本。在仓库根目录执行：

```bash
npm --prefix web ci
npm --prefix web run dev
```

浏览器打开 `http://127.0.0.1:4173/`。支持拖放/选择 TXT、DOCX、PDF，书架、阅读进度、批注备份恢复、Word 编辑导出、带批注 PDF 导出，以及自带渠道的 AI 对话；适配电脑和手机屏幕。`npm --prefix web run build` 生成可用普通静态服务器托管的 `web/dist/`。

网页端复用 Android 的阅读界面、PDF 和笔记模块，原文件存入当前浏览器的 IndexedDB，批注、进度和 Word 草稿使用 localStorage。数据不会自动同步到 Android 或其他浏览器；清除网站数据前请先导出。网页端 API Key 只保存在当前页面内存，刷新后需要重新填写；服务商须允许 CORS 浏览器跨域调用。复杂 Word 排版与真实 AI 服务仍有兼容性边界，详见 [网页端说明](web/README.md)。文中的 Keystore、Android 文件选择器和 Gradle 构建命令均指 Android 应用。

## Android 快速开始

环境要求：Android Studio、JDK 17、Android SDK 36，以及可执行的 Android SDK Platform 26+；首次准备语义模型另需 Node.js 20+ 和 curl。

```bash
git clone https://github.com/ZhangYukwiver/LightReader.git
cd LightReader
npm --prefix web ci
npm --prefix web run prepare:embedding
./gradlew assembleDebug
```

生成的调试 APK 位于 `app/build/outputs/apk/debug/app-debug.apk`。也可以直接在 Android Studio 中打开项目并运行 `app` 配置。

语义资源准备脚本固定模型版本并校验 ONNX 文件的 SHA-256；已有有效模型会复用。Android 资源中只有 q8 权重，fp32 权重保存在网页构建缓存中。24.0/94.9 MB 仅指模型权重，运行库、分词器和运行内存另计。已在 PHK110（Android 16 / WebView 155）验证真实 q8 建库、语义改写检索、暂停重启续建、完整索引复用、失败回退和原文定位：首次模型加载约 2 秒，1600 token 长段落分四窗计算约 2.7 秒且完整覆盖。上述为测试样本结果，尚未做长书或低内存压力测试，其他设备速度与兼容性可能不同。

发布前的基础检查：

```bash
./gradlew assembleDebug
./gradlew lintDebug
```

`app/src/test` 中保留了可从主方法运行的 DOCX/AI smoke check；它们不是 JUnit 测试，因此不会被 Gradle 的 `test` 任务自动发现。

AI 阅读助手另有 [24 段真实阅读材料评测](eval/README.md)，覆盖解释、翻译和追问，预先定义评分标准，并支持用 DeepSeek V4 Flash 记录 0.1.3 纯文本调整前后的真实输出、典型失败与响应耗时。

首次启动后：

1. 点击“导入”，从系统文件选择器选择 TXT、DOCX 或 PDF。
2. 选中文字即可添加批注、搜索或调用 AI 讲解/翻译。
3. DOCX 修改完成后点击“显示”进入编辑，再通过“导出 DOCX”保存副本。
4. 如需 AI，在“渠道设置”中填写服务商地址、模型和自己的 API Key；不配置也不影响本地阅读。
5. PDF 长按选中文字后点击“批注”；无可选文字的页面使用顶部“整页批注”。底部“批注”中可查看、编辑、跳转和备份；“导出含批注 PDF”通过系统文件选择器保存独立副本。PDF 原文件发生变化时，旧批注会保留为待定位，需要重新定位后才能导出带批注 PDF。

## 项目结构

```text
app/src/main/java/com/lightreader/app/
├── MainActivity.java          # 文件选择、WebView 容器和本地持久化
├── DocxRenderer.java          # 安全解析 WordprocessingML 并生成本地 HTML
├── DocxStyledExporter.java     # 将编辑后的样式块写回 DOCX
├── DocxPreservingExporter.java # 保留原包部件并附加批注
├── DocxExporter.java           # 无原包时的最小 DOCX 导出
├── AiClient.java               # HTTPS AI 请求与响应/引用解析
└── SecretStore.java            # Android Keystore 加密存储
```

界面和阅读交互集中在 `app/src/main/assets/reader.html`，通过受限的 JavaScript bridge 调用原生能力。`reader-pdf.js` / `reader-pdf.css` 负责 PDF 页面与选文层，`reader-pdf-export.js` 写入标准 PDF 批注，`PdfExportBuffer.java` 校验按文档隔离的分块导出数据，`reader-notes.js` 统一处理批注与备份。PDF.js 及其字体、CMap、WASM 解码器和 pdf-lib 随 APK 打包（来源和许可证见 `app/src/main/assets/vendor/`），运行时不访问 CDN。

批注数据检查：`node app/src/test/js/reader-notes-check.cjs`。PDF 浏览器检查使用 `app/src/test/js/create-pdf-fixture.py` 生成含英文、中文、旋转页和图像页的真实 PDF，再通过 Playwright CLI 运行 `reader-pdf-browser-check.js`。该检查仅模拟 Android bridge，不能代替真机文件选择、WebView 和持久化验收。

## 当前边界

- 目前支持 TXT、DOCX 和 PDF，不支持 EPUB。
- PDF 暂不支持密码解锁、OCR 和手写绘图。扫描页可添加整页批注；文字高亮需要 PDF 本身带有可提取的文字层。PDF 文件内原有批注在轻阅中只读，导出时原样保留；新批注仍可在原文档的轻阅笔记中修改后重新导出。
- 带批注 PDF 副本上限 40 MB，保留原有页面和交互批注，并在文末附上可直接阅读、打印的批注正文页（标明对应页码）。正文页以高清图像写入以兼容中文和不同阅读器；原文的文字层保留。重复导出同一副本不会重复添加已附上的正文；新增或修改的批注追加到文末。
- PDF 上限为 500 页、500 万提取字符；页面画布按可见范围加载并释放。需要支持现代 JavaScript 模块的 Android System WebView。
- 单个导入文件上限 20 MB；DOCX 渲染 HTML 和编辑草稿也有独立上限。
- AI 协议兼容性取决于服务商是否遵循对应接口；联网搜索需要 Responses 服务商支持 `web_search`。
- 当前没有云端同步、账号体系、多人协作或正式签名发布版 APK。
